# 6) الخطوط العربية واتجاه RTL والتشكيل

## الخطوط المضمّنة (قابلة للتوزيع)

| العائلة | الملفات | الترخيص |
|---|---|---|
| Amiri (نسخ كلاسيكي) | `Amiri-Regular.ttf`، `Amiri-Bold.ttf` | SIL Open Font License 1.1 |
| Tajawal (حديث بلا حروف مائلة) | `Tajawal-Regular.ttf`، `Tajawal-Bold.ttf` | SIL OFL 1.1 |
| Almarai (حديث) | `Almarai-Regular.ttf`، `Almarai-Bold.ttf` | SIL OFL 1.1 |

نصوص الرخص محفوظة في `drawing-tool/fonts/licenses/` (`Amiri-OFL.txt`, `Tajawal-OFL.txt`, `Almarai-OFL.txt`).
هذه الخطوط فقط تُضمَّن في المشروع وتُخدَم عبر `/fonts/*.ttf`؛ **لا تُنسخ أي خطوط من خطوط Windows المثبّتة إلى المشروع** (تُستخدم من النظام مباشرة وقت التشغيل، وهذا لا يتطلب ترخيص توزيع).

## خطوط النظام

عند التشغيل تُقرأ عائلات الخطوط المثبتة في النظام من مدير خطوط Skia.
على جهاز الاختبار: **236 سجل خط** تمثّل **233 عائلة فريدة**.

## كشف دعم العربية (فحص حقيقي لا افتراض)

`src/core/fonts.js → hasArabicGlyphs()` يرسم الحرف «م» مرتين:

1. مرة بالعائلة المطلوبة وحدها.
2. مرة بالعائلة نفسها مع خط عربي مرجعي (`Amiri`) كخط احتياطي.

إذا تطابق الرسمان فمعناه أن العائلة قدّمت الحرف بنفسها ⇒ تدعم العربية.
إذا اختلفا فمعناه أن محرّك التشكيل استعار الحرف من خط آخر ⇒ لا تُحتسب مدعومة.
النتيجة تُخزَّن مؤقتًا لكل عائلة.

النتيجة المقيسة على جهاز الاختبار: **58 سجلًا / 55 عائلة** تدعم العربية، منها الخطوط المضمّنة الثلاثة، وTahoma، Segoe UI، Simplified Arabic، Traditional Arabic، Sakkal Majalla، Dubai، Aldhabi، Arabic Typesetting، Andalus، وخطوط Diwani/Kufi/PT العربية الزخرفية… إلخ.
القائمة الكاملة تُطبع بالأمر: `node bin/artforge-draw.js fonts --arabic` أو عبر `font.list {arabicOnly:true}`.

## التشكيل (Shaping)

التشكيل يتم عبر HarfBuzz المدمج في Skia، أي وصل الحروف وتغيير أشكالها حسب الموضع في الكلمة.

دليل مقيس (`tests/engine.test.js`):
- عرض `"مرحبا"` = 107.18 وحدة
- عرض `"م ر ح ب ا"` (حروف منفصلة) = 185.27 وحدة

الفارق الكبير يثبت أن الحروف تُوصل فعليًا ولا تُرسم منفصلة.

## الاتجاه RTL

- يُكتشف تلقائيًا بوجود أي محرف من نطاقات العربية/الفارسية/العبرية (`text.js → RTL_RE`).
- المحاذاة الافتراضية للنص العربي: `right`. وعند `align:'right'` تكون `x` هي **حدّ النص الأيمن**، و`y` أعلى السطر الأول.
- النص المختلط (عربي + لاتيني + أرقام) يُعالَج على مستوى المقاطع (runs) بواسطة HarfBuzz؛ مثال مُختبَر بصريًا: `Mixed: ArtForge تصميم 2026` يظهر بترتيب صحيح لكل مقطع.
- **قيد معروف**: خيار `ctx.direction` غير متاح في خلفية Node، لذا لا يمكن فرض اتجاه فقرة قسريًا؛ يُعتمد على محتوى النص ومحاذاة العنصر. المتصفح يدعم `direction` أصلاً.

## التفاف النص

عند تمرير `maxWidth` يقسّم المحرّك النص على المسافات ويلفّ الأسطر بما لا يتجاوز العرض، ويُعيد `text.measure` عدد الأسطر وعرض كل سطر والارتفاع الكلي قبل الرسم (مفيد لحساب التخطيط).

## تباعد الحروف (letterSpacing)

- في المتصفح: مدعوم عبر `ctx.letterSpacing`.
- في Node: غير مدعوم في هذه النسخة من Skia، ويُتجاهَل مع تسجيل تحذير في `warnings` عند التصدير.
- لا يُنصح باستخدامه مع العربية إطلاقًا لأنه يفصل الوصلات.

## أمثلة استدعاء

```json
{ "op": "draw.text",
  "params": { "documentId": "doc_x", "x": 1100, "y": 200,
              "text": "نص عربي متعدد الأسطر يلتف تلقائيًا",
              "font": { "family": "Tajawal", "size": 44, "weight": 400, "lineHeight": 1.6 },
              "align": "right", "maxWidth": 700, "fill": "#e5edf7" } }
```

```json
{ "op": "text.measure",
  "params": { "text": "قياس النص قبل الرسم", "font": { "family": "Amiri", "size": 40 }, "maxWidth": 300 } }
```

```json
{ "op": "font.list", "params": { "arabicOnly": true } }
```
